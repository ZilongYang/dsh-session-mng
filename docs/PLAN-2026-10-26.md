# dsh-session-mng 0.1.0 实施计划

> 公开版说明：本文件为脱敏版；逐字原文保存在 `private/raw-plans/PLAN-2026-10-26.md`（已被 `.gitignore` 忽略，不随仓库发布）。脱敏项：`<workspace>`、`<npm-account>`。


> 目标：在当前工作区 `<workspace>` 从零开发一个 DSH（DeepSeek Harness）Host + Web Client 双半插件，把「会话总览 / 生成标题 / 归档与恢复 / 跨工作区移动 / 彻底删除」收进一个设置页，然后开源到 `ZilongYang/dsh-session-mng`、发布 npm `dsh-session-mng`，并向 awesome-dsh-plugin（dshmarket / 社区插件目录的数据源）提交收录 PR。

## 1. 目标与验收标准

### 1.1 功能目标

1. **统一会话总览**：设置页新增「会话管理」；按工作区分组列出当前 profile 的全部会话（活跃 + 已归档），显示标题、路径、工作区、大小、最后活动时间、运行/归档/子会话标记；支持标题/路径/id 过滤、排序、刷新、批量选择。
2. **生成标题**：选中任意会话（含**已归档的冷会话**）后，用大模型总结整段对话，给出可编辑的标题提案，**确认后才写入**；活跃会话走官方 `sessionTitle.rename`，冷会话按官方事件形状追加 `session/title`，不需要恢复会话。
3. **归档 / 恢复**：调用官方 `workspaceRegistry.archiveSession` / `unarchiveSession`；运行中的会话先提示，用户二次确认后才 `stopActivity`；恢复后回到原工作区原位置。
4. **跨工作区移动**：把冷会话真正迁移到目标工作区——改写会话日志 header 的 `cwd`、把日志目录搬到目标项目目录、同步 workspace 账本；保持 SessionId 不变、归档状态不变、事件字节不变；活跃/运行中的会话拒绝移动并说明原因。
5. **彻底删除已归档会话**：只允许删除已归档会话；确认后删除日志目录、清理归档集合与工作区账本；若会话有子代理后代，二次确认中明确列出并级联删除，避免留下孤儿日志。不可恢复。
6. **辅助能力**：最近消息预览、删除范围预览（会话数/字节数/子会话数）、磁盘占用统计、失效归档标记清理、中英双语。

## 2. 已核实的事实（决定设计）

这些是本次探索中从当前 DSH 0.2.1-rc.2、profile `desktop`、已安装包源码/类型、运行中的 Inspect 和真实数据目录确认的，不是假设：

1. **工作区归属是派生的，不是存储的**：workspace 的 `sessionIds` 是 header 校验后的投影；一个会话属于某工作区，当且仅当其**存储 header 的 `cwd`** realpath 等于该 workspace 的 `path`。因此「移动工作区」必须改写会话日志 header 的 `cwd`，只改账本无效。
2. **归档集合是 registry-global 的**：`workspaceRegistry.archivedSessionIds` 存会话 id；归档不改变 workspace 归属；恢复只是从集合移除 id，所以能回到原位置。
3. **会话日志物理布局**（JSONL 后端）：`~/.dsh/sessions/--<projectKey(cwd)>--/<encoded-id>/session.vN.jsonl[.zstd]`；第一个 zstd frame 是物理 header（一行 JSON，含 `cwd`），后续 frame 是追加事件。当前运行环境 Node 24.21 的 `node:zlib` 有 `zstdCompressSync`/`zstdDecompressSync`（Electron 主进程同样验证过）。
4. **`sessionPersistence.locate({ id, cwd })` 存在**（当前 JSONL 后端的 duck-typed 方法，不在抽象接口里），可据此推导源/目标会话目录，不必自己实现 `projectKey` 编码。
5. **删除没有官方 API**：seam 明确「日志在 root 下累积，直到外部移除；无删除接口」。彻底删除必须走文件系统，并同时清理归档集合与 workspace 账本。
6. **标题是日志事件**：`session/title` 事件 `{ title, messageSeqs, source:{kind:'user'} }`；`sessionTitle.rename(liveSession, title)` 是官方写入路径，要求会话已 live。冷会话可以用 `sessionPersistence.open(id,'write')` + `handle.append([{type:'session/title', seq:last+1, time, data}])` 写入**完全相同形状**的事件，不必恢复 Agent。
7. **workspace 有内存 header 缓存**：`workspaceRegistry.headers` / `sessionPaths` 在启动时建立；`attachSession` 读缓存而不是重新读盘。移动后若不更新这两处，`attachSession` 会拿旧 cwd 校验失败，侧栏也会过滤掉会话。当前可行做法（社区 `dsh-session-drag-move` 已采用）是 `registry.headers.set(id, newHeader)` + `registry.host.rememberSessionPath(id, target.path)` + `invalidSessionPaths.delete(id)`，再走公开 `attachSession` / `detachSession`。这是**版本敏感的内部 seam**，必须做特性检测和失败回滚。
8. **会话列表**：`sessionController.list({}, signal)` 返回所有可见摘要（含已归档），带 `updatedAt`、`running`、`blank`、`cwd` 与 projections（含 `title`）；`sessionQuery.listSessions()` 是完整语料兜底；`sessionQuery.readTitleSnapshots(ids)` 可批量折叠标题。
9. **UI 落点**：`settings.section`（list）在设置面板内容列渲染，owner props 提供 `close`；`label` 支持 thunk。当前占用含 `ds-arch-section`（order 80）。我们的 section 用 `order: 82`、id `session-mng-section`，与现有归档插件共存。
10. **市场规则**：awesome-dsh-plugin 一个插件一个文件 `data/plugins/<owner>__<repo>.yml`，分类 `session`；必须有 `dsh.bundle`、`dsh-plugin` topic、仓库满 1 天；截图放自己仓库的 `screenshots.json`（1–8 张）；npm 包可选但推荐；同一 PR 最多 3 条。dshmarket 直接消费这份目录，**不需要第二次提交**。
11. **名称与账号**：npm `dsh-session-mng` → 404（可用）；`dsh-session-manager` 已存在（不用）；GitHub `ZilongYang/dsh-session-mng` 不存在（可用）；`gh` 已登录 `ZilongYang`，npm 已登录（账号名不写入公开文档）。
12. **同类插件很多**（`dsh-session-drag-move`、`dsh-session-move`、`dsh-session-delete`、多个 `archive-manager`、`dsh-session-explorer` 等）。本插件不靠“单点功能首创”，而靠**一个控制台覆盖完整生命周期**、**已归档会话也能生成标题**、**批量 + 大小/预览 + 删除范围预览**、**无 agent 工具、零提示词开销**来形成差异。

## 3. 范围与非目标

### 3.1 0.1.0 范围

- Host：一个 HTTP API + 服务实现 + 文件事务 + workspace 对账；不注册模型可见工具。
- Client：只在 `settings.section` 注册一个页面；不做侧栏菜单、不做 header 按钮、不做全局 overlay。
- 支持 backend：本地 JSONL（移动/删除）；其他 backend 仍可使用总览/标题/归档/恢复，移动/删除在 UI 中禁用并说明。
- 支持会话：普通用户会话、fork 会话（`isSeeded:true` 且无 parent）；**不移动** `origin:'subagent'` 或有 `parentSession` 的子会话；**不移动** 有后代的会话（避免父子分居）；删除时**级联**删除后代。
- 永久删除：无回收站（用户明确要求「彻底删除」）；仅在事务内部使用临时目录做原子性保护，成功后立即删除。

### 3.2 非目标（0.1.0 不做）

- 不做自动标题 provider、不做自动归档规则。
- 不做回收站/撤销删除。
- 不做非 JSONL backend 的移动/删除。
- 不做远程/SSH 会话根目录的跨主机迁移（只操作本 Host 的 `sessionPersistence`）。
- 不做侧栏菜单/顶栏按钮/内容全文搜索/导出/置顶/分叉（列入 ROADMAP 0.2.0）。
- 不修改 `dsh-session-titler`、`@chushiz/dsh-archive-manager` 或任何官方包。

## 5. 技术设计

### 5.1 Host 入口与注入

`index.js`：

```js
export const name = 'session-mng'
export const inject = [
  'webServer', 'sessions', 'sessionQuery', 'sessionPersistence',
  'workspaceRegistry', 'sessionTitle', 'llm',
]
export function apply(ctx, config) { /* normalize config, mount route once */ }
```

- `sessionController`、`agents` 用 `ctx.get(...)` 惰性获取（缺失时降级：`updatedAt` 用 header/mtime，删除时不尝试停 Agent）。
- 路由挂载沿用 titler 的幂等策略：`globalThis[Symbol.for('dsh-session-mng/route')]` 记录上一条 prefix 注册；重复安装（市场副本 + profile bundle）时新挂载接管旧路由，dispose 只删除自己仍拥有的那条。
- 不 `ctx.provide` 新服务，避免重复安装时的服务冲突；HTTP 路由是唯一入口。

### 5.2 配置（`apply(ctx, config)` 读取并 clamp）

| key | 默认 | 说明 |
|---|---|---|
| `maxBatch` | 50 | 归档/恢复/删除单次最多 id 数 |
| `maxMoveBatch` | 20 | 移动单次最多 id 数 |
| `titleTimeoutMs` | 30000 | 单次标题模型调用超时 |
| `titleMaxInputBytes` | 32768 | 送入模型的 transcript 预算 |
| `titleMaxOutputTokens` | 256 | 标题输出上限 |
| `titleMaxBytes` | 120 | 接受标题的 UTF-8 字节上限 |
| `allowRemote` | false | 是否允许非 loopback/trustedHosts 请求（默认否） |
| `sessionsRoot` | '' | 仅在 `sessionPersistence.locate` 缺失时用于定位根目录；默认 `~/.dsh/sessions` |

所有数值做边界校验；非法值回退默认并 `ctx.logger.warn`。

### 5.3 HTTP API

统一前缀 `/session-mng/api`；除 `state` 外全部 POST；JSON 信封：

```jsonc
{ "ok": true, "value": { ... } }
{ "ok": false, "error": { "code": "session-live", "message": "...", "details": { ... } } }
```

| 方法/路径 | 请求 | 返回 |
|---|---|---|
| `GET /state?subagents=0\|1` | — | `{ workspaces, sessions, ungrouped, orphans, capabilities, totalBytes, backend }` |
| `POST /preview` | `{ sessionId, count? }` | `{ messages:[{role,text,time}], total }` |
| `POST /title/propose` | `{ sessionId }` | `{ title, provider, model, fallback, messages, truncated }` |
| `POST /title/apply` | `{ sessionId, title }` | `{ title, seq, mode:'live'\|'cold' }` |
| `POST /archive` | `{ sessionIds, stopActivity? }` | `{ totals, results }` |
| `POST /unarchive` | `{ sessionIds }` | `{ totals, results }` |
| `POST /delete/preview` | `{ sessionIds }` | `{ roots, descendants, sessions, totalBytes }` |
| `POST /delete` | `{ sessionIds, confirm:true }` | `{ totals, results }` |
| `POST /move` | `{ sessionIds, workspaceId }` | `{ totals, results }` |

- body 上限 64 KiB（`content-length` 预检 + 流式累计）；ID 必须是 host 当前 state 中存在的 id；workspaceId 必须来自 `workspaceRegistry.list()`；不接受路径/命令参数。
- 单个 id 的业务失败放进 `results`（HTTP 200），全局失败才用 4xx/5xx。
- `state` 返回 `capabilities`：`{ move:boolean, delete:boolean, title:boolean, backend:'jsonl'|'other' }`；`sessions` 每行带 `can:{title,archive,restore,move,delete,open}`，客户端只做展示。
- 所有响应 `cache-control: no-store`。

### 5.4 会话总览（`state.js`）

数据来源：

1. `sessionController.list({}, AbortSignal.timeout(15000))` 主来源；失败则回退 `sessionQuery.listSessions()`。
2. `sessionPersistence.list()` 提供 header、`sizeBytes`、`formatStatus`。
3. `workspaceRegistry.list()` 提供工作区顺序、路径、`status()`；`sessionIds` 作为**权威归属**；不在任何账本的会话按 `header.cwd === workspace.path` 兜底，仍无匹配则 `ungrouped`。
4. `sessionQuery.readTitleSnapshots(ids)` 只为缺失标题的 id（已归档/无 projection 缓存）批量补读；活跃摘要优先用 `projections.values.title`。
5. 归档集合/置顶集合来自 `workspaceRegistry.archivedSessionIds` / `pinnedSessionIds`。
6. `orphans`：归档集合中在 persistence 里找不到 header 的 id（用于「清理失效归档标记」）。

每行：

```ts
{
  id, title, cwd, workspaceId, workspaceTitle, archived, pinned, live, running, blank,
  origin, parentSessionId, agentPreset, createdAt, updatedAt, sizeBytes, formatStatus,
  isSubagent, can: { title, archive, restore, move, delete, open }
}
```

规则：

- 默认过滤 `isSubagent`（`GET /state?subagents=1` 才返回）；子会话不参与分组/批量。
- 标题为空时显示 `(未命名)`，但**不**自动生成。
- `sizeBytes` 取当前 generation 的 `stat.sizeBytes`（UI 标「约」）；删除预览时另外递归计算目录真实字节。
- `move` 的 can 条件：`!live && !running && !isSubagent && !parentSessionId && backend==='jsonl' && !hasDescendants`。`hasDescendants` 在 state 中不展开（避免全量 trace），由 `move` 操作内部检查并返回明确错误。
- `delete` 的 can 条件：`archived && backend==='jsonl'`；有后代也可删（级联），由 UI 二次确认。
- `live` 用 `ctx.sessions.get(id) !== undefined`；`running` 优先 `summary.running`，兜底 `agents.get(id)?.status === 'running'`。

### 5.5 标题（`title.js`）

**提案（只读，零写入）**：

1. `ctx.sessionQuery.readSurface(sessionId)` 读取当前模型表面；抽取 `user/message` 与 `assistant/message` 的 text block。
2. 按 titler 的策略：每条 user ≤2000 字符、assistant ≤3000 字符；整段 JSON ≤32 KiB；超出时从中间删 turn，保留头尾；标记 `truncated`。
3. 路由候选（新→旧）：live `session.requestHeader()?.config` → 日志中每条 `request/header` 倒序 → `agentDefaultModel.currentSelection()`；每个候选用 `llm.listProviders()` 过滤不可用的 provider；没有候选则返回 `no-adapter`，并带上会话记录的 route。
4. 调用 `ctx.llm.stream({ provider, model, system, messages, maxTokens:256, sessionId, purpose:'session-title', signal })`；没有 `stream` 时按 titler 的 `prepareCall` 回退。只收集 `text-delta`，处理 `finish`（stop / aborted / error / max-tokens / tool-calls）。
5. 标题清洗：去 OSC/CSI/ESC/控制字符/方向控制符，压缩空白，取第一个非空行，UTF-8 截断到 120 字节；空标题报 `llm-error`。
6. 返回 `{ title, provider, model, fallback, messages, truncated }`；`fallback=true` 表示没用会话自己记录的模型。

**写入（确认后）**：

- **live**：`const live = ctx.sessions.get(id)`；`ctx.sessionTitle.rename(live, title)`（官方路径，自动处理 normalization/pin/事件）。若 `sessionTitle` 不可用则报 `unsupported-host`。
- **cold**：`open(id,'write')` → `read()` 全量事件 → 若最新 `session/title` 文本已等于目标则直接返回 no-op → `append([{ type:'session/title', seq: lastSeq+1, time: Date.now(), data:{ title, messageSeqs:[], source:{kind:'user'} } }])` → `flush()` → `close()`。
  - 写句柄会拿内核写锁；被其他进程占用时返回 `session-writer-held`，不重试。
  - 历史 generation 的写 open 会由后端迁移到当前 generation，属于官方行为。
  - 写入后用 `readTitleSnapshots([id])` 复核；失败则报错（事件可能已写入，UI 刷新后可见）。
- 不做批量标题（0.1.0 单会话，避免一次触发多个模型调用）。

### 5.6 归档 / 恢复

- 归档：`workspaceRegistry.archiveSession(id)`；若抛 `WorkspaceActiveSessionError`（或错误带 activity），返回 `{code:'session-active', activity}`；客户端提示「停止并归档」，用户确认后重试 `{stopActivity:true}`。
- 恢复：`workspaceRegistry.unarchiveSession(id)`；客户端可选「恢复并打开」：成功后调用 `ctx.get('uiWorkspace')?.openSession(id)`，并 `close()` 设置面板。
- 两者都是官方写路径，不需要文件事务；批量顺序执行，逐 id 返回结果。
- 归档/恢复后客户端重新拉 `state`；侧栏通过 registry 的持久化写事件更新（若宿主缓存未刷新，刷新页面）。

### 5.7 跨工作区移动（`store-jsonl.js` + `workspace-sync.js`）

这是全插件风险最高的操作，采用**先备份、再复制、后对账、失败全回滚**的事务，不直接改写原目录。

**前置校验（任何写盘之前）**：

1. `capabilities.move` 为真（JSONL + `locate` + zstd）。
2. `sessionPersistence.stat(id)` 存在；`header.cwd` 存在且为绝对路径。
3. `ctx.sessions.get(id) === undefined`；`agents.get(id)?.status !== 'running'`；否则 `session-live` / `session-running`。
4. 目标 workspace 存在、`status()==='ok'`、`target.path !== 当前 header.cwd`（同一工作区则 no-op）。
5. 不是 subagent（`header.origin !== 'subagent'` 且无 `parentSession`）。
6. `sessionQuery.traceSession(id)` 的 `descendants` 为空；否则 `has-descendants`（提示先处理子会话）。
7. 源目录唯一：`dirname(locate({id, cwd: header.cwd}))` 存在则用之；否则在 root 下扫描 `session.v*.jsonl*` 的 header 匹配 id（`cwd` 已失效时的兜底）；找到 0 个 → `not-found`，找到 >1 个 → `duplicate-session`。
8. 目标目录不存在（`locate({id, cwd: target.path})` 的 dirname）；已存在 → `move-conflict`。
9. `sessionPersistence.open(id,'write')` 成功拿到写锁后立刻 `close()`，确认没有其他进程正在写；失败 → `session-writer-held`。
10. `typeof sessionQuery.readSession(id)` 成功，证明日志可完整重放；失败 → `unreadable-session`，拒绝移动。

**事务步骤**：

```
root        = dirname(dirname(sourceDir))               // <root>/<project>/<id>
backupRoot  = join(dirname(root), '.dsh-session-mng-tmp') // 必须在 sessions root 之外，避免被 list() 扫到
backupDir   = join(backupRoot, `${id}-${timestamp}-${rand}`)
targetDir   = dirname(locate({ id, cwd: target.path }))

1. mkdir(backupRoot)
2. rename(sourceDir, backupDir)                 // 源目录原子移出 root；失败 → EXDEV 时 cp+rm，失败即中止
3. cp(backupDir, targetDir, { recursive:true, preserveTimestamps:true })
4. 读 targetDir 当前 generation 日志，找到第一个 zstd frame（magic 扫描 + 逐候选解压验证 header.id/type/cwd），
   把 header 的 cwd 改成 target.path，重新 zstdCompressSync 该帧，拼回其余字节；
   raw（compression:none）则替换第一行。写临时文件 → fsync → rename 为正式文件（mode 0600）。
5. 复核：重新解析 target 日志 header == { ...oldHeader, cwd: target.path }；且 readSession(id) 成功、事件数不变。
6. 对账（workspace-sync）：
   registry.headers.set(id, newHeader)
   registry.host.rememberSessionPath(id, target.path)
   registry.invalidSessionPaths.delete(id)
   await target.attachSession(id)                 // 公开 API
   await source?.detachSession(id)                // 公开 API
7. rm(backupDir, { recursive:true, force:true })
8. 返回 { moved:true, from:source?.id, to:target.id, cwd:{from,to}, bytes }
```

**回滚**（步骤 3–6 任一失败）：

1. 若 `target.attachSession` 已成功，尝试 `target.detachSession(id)`。
2. 恢复 registry 缓存：`registry.headers.set(id, oldHeader)`、`host.rememberSessionPath(id, sourceWorkspace.path)`（或删除该路径缓存）；`invalidSessionPaths.delete(id)`。
3. `rm(targetDir, {recursive:true,force:true})`。
4. `rename(backupDir, sourceDir)`；若 EXDEV 则 cp+rm。
5. 返回原始错误；若回滚本身失败，返回 `{ code:'manual-recovery', details:{ sourceDir, targetDir, backupDir } }` 并在 README 给出恢复步骤。

**内部 seam 特性检测**：

- 写盘前检查 `registry.headers instanceof Map`、`typeof registry.host?.rememberSessionPath === 'function'`、`typeof target.attachSession === 'function'`、`typeof target.detachSession === 'function'`。
- 任一缺失：**不移动**，返回 `unsupported-registry`，提示「当前 DSH 版本的 workspace 缓存接口已变化，请升级插件或改用重启后重建归属」。
- 这条依赖写在 README 的「兼容性」和 `docs/01-design.md`，并只在实测过的 0.2.1-rc.2 声明兼容。

**已知限制**（必须在 UI/README 明说）：

- 已打开（live）的会话不能移动；切换/关闭会话不会立刻销毁进程内 Session，最可靠的是重启 DSH 后移动。
- 有子代理后代的会话不能单独移动（0.2.0 再支持整枝移动）。
- 移动会复制整个会话目录（含历史 generation），大日志会慢；批量上限 20，逐条执行。
- 移动后归档状态、pin 状态、SessionId 都不变；标题投影缓存因 header 身份变化会自动失效并在下次读取时重折。

### 5.8 彻底删除（只删已归档）

**删除范围预览** `POST /delete/preview`：

- 每个 root 必须 ∈ `archivedSessionIds`，否则该条 `code:'archived-required'`。
- `traceSession(root)` 收集全部后代 id（递归）；后代不要求已归档。
- 对每个 id 找目录、递归算字节、尝试 `readSession`（只标记可读/损坏，不阻止删除）。
- 返回根会话列表、后代数量/列表、总字节、警告（损坏/目录缺失/重复目录）。

**执行** `POST /delete`：

1. 校验 `confirm === true`；重新校验 root 仍已归档（防 TOCTOU）。
2. 重新计算删除集合（roots + descendants），去重；总量超 `maxBatch` 拒绝。
3. 对每个 id：若 `agents.get(id)` 存在且 running，`cancel({kind:'disposed'})` + `await whenIdle()`；失败则整批中止。
4. 事务：把每个存在的会话目录 `rename` 到 `backupRoot/delete-<batch>-<id>`（root 之外）；记录映射。
5. 清理 registry（对每个 id）：
   - `workspaceRegistry.unarchiveSession(id)`（对未归档 id 是 no-op）；
   - 找到所属 workspace（`sessionIds.includes(id)`），`await ws.detachSession(id)`；
   - 可选：`registry.headers?.delete(id)`、`sessionPaths?.delete(id)`（特性检测，best effort）。
6. 成功 → `rm(trashDirs, {recursive:true,force:true})` 并验证不存在；返回每 id 结果与释放字节数。
7. 步骤 5 失败 → 把 trash 目录 `rename` 回原位；对已 unarchive 的 root 尝试 `archiveSession(id)` 恢复原状态；返回错误。步骤 6 失败 → 数据仍在 trash，返回 `{code:'leftover-trash', details:{paths}}`，提示重试/手动清理；**不谎报成功**。
8. 目录本来就不存在（已被外部删除）→ 仍清理 registry，返回 `alreadyGone:true`。

**安全边界**：只接受 state 中存在的 id；只删 `sessionPersistence` 定位到的目录；临时目录必须在 sessions root 之外；不使用 shell、不接受路径参数。

### 5.9 预览

`POST /preview {sessionId, count}`：

- 优先 `sessionQuery.readSurface(id)`；失败回退 `readSession(id)`。
- 从尾部向前取 user/assistant 文本，最多 10 条，保持时间顺序；text 压平、最多 2000 字符；不展示工具调用/推理。
- 返回 `{messages, total}`；损坏日志返回可读错误。

### 5.10 Client UI（`client.js`）

**注册**：只注册 `settings.section`，id `session-mng-section`，order 82，`label: () => t('navLabel')`；`ctx.slots.inject('settings.section', () => ctx.slots.register({...}, Page))`。不注册 `shell.overlay`、不注册侧栏菜单，避免与 titler/官方菜单/归档插件冲突。

**页面结构**：

1. 顶部：标题「会话管理」、副标题、刷新按钮、统计（共 N 个会话 / M 个已归档 / 约 X MB）。
2. 过滤栏：tabs（全部/活跃/已归档）、工作区下拉、搜索框（标题/路径/id）、排序（最近活动/创建时间/大小/标题）、「显示子会话」开关（切到 `?subagents=1` 重新拉取）。
3. 批量条：选中 N 个时出现；归档（仅活跃）、恢复（仅已归档）、移动到…、彻底删除（仅已归档）、清除选择；不兼容的按钮禁用并说明。
4. 列表：按 workspace 顺序分组；组头显示标题、路径、会话数、总大小、目录缺失警告；行显示 checkbox、标题、路径尾、标签（运行中/已归档/子会话/无标题）、相对时间、大小、操作按钮（打开/详情）。
5. 详情视图（点击行进入，页面内切换，不做 modal）：
   - 元信息：id（点击复制）、完整路径、workspace、创建/更新时间、大小、formatStatus。
   - 操作区：生成标题 / 打开 / 归档 / 恢复并打开 / 移动到工作区 / 彻底删除（仅已归档）。
   - 预览区：加载最近 10 条消息。
   - 标题区：点「生成标题」→ 加载中 → 可编辑 input + 模型/回退说明 + 重新生成/应用/取消；应用成功后更新本行并 toast。
   - 移动区：目标 workspace 下拉（当前工作区、missing-dir 禁用）、警告文案、确认按钮。
   - 删除区：红色警告、路径/大小/子会话数、「预览删除范围」→ 列表/总字节、勾选「我已了解不可恢复」后确认。
6. 底部/顶部状态条：最近一次操作结果、逐条失败摘要（可展开）。
7. 空状态/加载骨架/错误重试。
8. 快捷键：`Esc` 从详情返回列表；`/` 聚焦搜索框（可选）。

**样式**：类名前缀 `dsm-`；只用 `Theme.listTokens` 的 `--dsw-alias-*` 颜色 + 自持的 px 圆角/间距；浅色/深色都要可读；不复用 Harness Client 包；不写 `document.body`；样式用 `<style data-plugin="dsh-session-mng">` 在 `ctx.effect` 里挂载/清理。

**状态**：`useState`/`useEffect`；`fetch` 同源相对路径；`AbortController` 取消在途请求；窗口 `focus` 时静默刷新；所有可见文案走 `ctx.locale` 的 zh/en 字典；locale 变化订阅并重渲染。

**打开会话**：`ctx.get('uiWorkspace')?.openSession(id)`；恢复并打开时先 `await` API 再关闭设置（`props.close?.()`）并打开。服务缺失则隐藏「打开」。

## 6. 安全、失败与数据保护

- **路由围栏**：Host header 必须是 loopback 或 `webRuntime.trustedHosts`；`Sec-Fetch-Site: cross-site` 拒绝；`Origin` hostname 必须与 Host 一致；`allowRemote` 默认 false。复制 titler 的 fence 实现并保留注释。
- **无任意路径/命令**：API 只接受 session id 与 workspace id；所有路径由 `sessionPersistence.locate` + 受控扫描推导；不使用 `shell`，不做字符串拼接命令。
- **写锁**：移动/标题写冷日志前先尝试写句柄；被占用即失败，不抢锁。
- **原子性**：移动/删除都先把目录移出 sessions root 到同文件系统的临时目录，失败可回滚；成功后才删除临时副本。
- **不记录内容**：日志只记录 action、session id、workspace id、结果码；不记录标题/消息/路径全文。
- **无隐式写入**：标题提案阶段零写入；归档/恢复/移动/删除都必须由 UI 明确点击；删除需要 `confirm:true` + 勾选。
- **不碰其他插件**：不修改 profile、不写 `cordis.patch.yml`、不注册模型工具、不注册 title provider。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| workspace 内部缓存接口变更 | 写盘前特性检测；缺失即拒绝并回滚；只声明实测过的 0.2.1-rc.2；`docs/01-design.md` 说明；单测覆盖 |

| 移动后 registry 账本不一致 | 事务 + 回滚；失败返回 `manual-recovery` 与路径；重启后 registry 会从持久化重建 |

## 事后差异（补记，2026-10-27）

> 本节是实施完成后补记，不属于批准时的计划正文。

1. **彻底删除对 live/running 会话改为直接拒绝**。计划原写「若 running 则 cancel + whenIdle」；实测发现 live Session 删除后仍会留在进程内 Session store，侧栏会出现幽灵行直到重启。实现改为：`ctx.sessions.get(id) !== undefined` 或 agent running 时直接返回 `session-live` / `session-running`，并在 UI 的 `can.delete` 中关闭；提示重启 DSH 后重试。更安全，也避免「文件已删但内存里还在」的不一致。
2. **Client 只注册 `settings.section`，没有侧栏菜单/顶栏按钮/全局 overlay**。与计划一致，但实现上把「详情」做成页面内切换而不是 modal；同时补了滚动位置复位、批量条 sticky、选中行高亮。
3. **`uiWorkspace` 只能用 `ctx.get('uiWorkspace')` 获取**。Cordis Client 上下文对未 inject 的服务做直接属性访问会抛 `cannot get property ... without inject`；最初的 `ctx.uiWorkspace ?? ctx.get(...)` 被 try/catch 吞掉，导致「恢复并打开」不显示。已改为仅 `ctx.get`，并实机确认按钮出现。
4. **冷标题写入后增加 `readTitleSnapshots` 复核**，失败返回 `title-verify-failed`；计划只要求写入事件。
5. **移动对 header 帧的验证更严格**：zstd magic 候选必须解压出合法 header 才接受；写盘后除 header 复核外还完整 `readSession` 一次并比对事件数。
6. **删除预览补充 `live` / `running` / `readable` 标记**，UI 用它们阻止不可执行范围。
7. **截图使用 demo 数据 + 折叠侧栏**，避免把真实工作区名、会话标题、路径带进公开仓库；三张图分别对应总览、标题提案、删除范围。
8. **计划里的「子代理级联删除」保留**：实现通过 `sessionQuery.traceSession` 收集后代，确认面板显示根/子数量与总字节；未在真实用户数据上执行，只用测试会话与 demo 预览验证。
9. **发布步骤尚未执行**：本地 git 初始化/公开仓库、npm publish、awesome-dsh-plugin PR 待用户明确同意后逐项进行；当前 `docs/02-open-source-and-marketplace.md` 与 `docs/RELEASE-CHECKLIST-0.1.0.md` 已写好 runbook 与待勾选项。
