## 一、适配结论（为什么 P0/P1 是这些内容）

### 1.1 实测：0.2.2-rc.3 上零破坏

| 检查 | 结果 |
|---|---|
| `GET /session-mng/api/overview` | 200，`source: "catalog"`（零 IO 快路径生效，未回退 `buildState`） |
| `GET /session-mng/api/sessions?workspaceId=…` | 200，行字段齐全（`forkLineage` / `membership` / `can.*`） |
| `GET /session-mng/api/misplaced` | 200，`count: 0` |
| `npm test` | 144/144 通过 |

### 1.2 升级指南对照

`docs/upgrade-guide/README.md` 索引中：rc.1 → rc.2 有 19 条指南；**rc.2 → rc.3 无新增目录**（无公开破坏面）。19 条里与本插件使用面（`workspaceRegistry` / `sessionQuery` / `sessionPersistence` / `sessionProjections` / `sessionTitle` / `llm` / `webServer` / 客户端 `settings.section`）相交的**只有 `archive-worktrees` 一条**，其余（Forge、CUA、账号、终端、Web 搜索计费、`BundleInfo.update`、`Session.append` 重载、`window-drag-regions`）不涉及本插件。

**结论：不需要紧急改代码。** 需要补的是兼容矩阵条目（`dshReleases` 只到 `0.2.2-rc.1`）和归档×工作树的安全网。

### 1.3 顺带发现的真问题（与升级无关，但更该修）

实测 `POST /session-mng/api/preview`（会话 `b5946f88…`）返回的「最近消息」5 条**全是系统注入**：`<system-reminder>`、技能目录、时间上下文、MNEMON 快照。

统计最近 120 个会话日志的 `user/message` 事件分布：

| `source.kind` | 条数 | 占比 | 性质 |
|---|---|---|---|
| `user` | 315 | 28% | 真人输入（含子代理任务下发） |
| `time-context` | 304 | 27% | 每轮注入的快照 |
| `runtime-context` | 151 | 13% | `<system-reminder>` 快照 |
| `dsh-mnemon` | 148 | 13% | instructions / memory-snapshot / recall |
| `skill-catalog` | 45 | 4% | 技能目录 |
| `user-approval` | 12 | 1% | 审批策略变更通知 |
| `tool-jobs` | 12 | 1% | 后台任务通知 |
| `agent-message`（form=relay） | 9 | 1% | 别的 agent 发来的真实内容 |
| `subagent-settled` | 9 | 1% | 子代理结束通知 |

根因：`lib/title.js:collectTurns()` 与 `lib/service.js:preview()` 只判断 `event.type === 'user/message'`，不看 `data.source.kind`。影响「最近消息」面板（永远被提醒占满）与整段标题生成（噪音淹没输入，`shrinkToBudget` 还会从中间删掉真实轮次）。

## 二、P0：消息口径修复

### 2.1 判定规则

允许清单：`user`、`agent-message`（form=relay）、**无 `source` 字段**（老日志）。
丢弃：`time-context`、`runtime-context`、`skill-catalog`、`dsh-mnemon`、`user-approval`、`tool-jobs`、`subagent-settled` 以及任何未知新 kind。

兜底策略：
- **标题生成**过滤后若一个用户轮都没有，退回旧口径（保证任何会话仍能出标题）；
- **最近消息预览不兜底**，显示空态（宁缺毋滥）。

### 2.2 改动

| 文件 | 改动 |
|---|---|
| `lib/title.js` | 新增 `isConversationalUserMessage(event)`；`collectTurns()` 支持过滤 + 兜底 |
| `lib/service.js` | `preview()` 复用同一判定，响应新增 `skipped`（加法） |
| `client.js` | 预览面板 `skipped > 0` 时显示「已隐藏 N 条系统注入」；中英双语文案 |
| `test/` | 混合 kind fixture、纯注入兜底、无 source 老日志、`agent-message` 保留 |

## 三、P1：归档 × 工作树安全网

### 3.1 宿主行为（rc.2 起）

工作树服务把创建的检出目录记成 `plugin:worktree/created` 记录；会话归档时，若该记录**属于本会话（`owned: true`）**、无未归档会话引用、策略非只读、Git 检查干净，就 `git worktree remove`（分支保留；被忽略与未提交文件丢失）。本插件归档走 `registry.archiveSession()`，同样触发。

现状：`~/zWork/ai/*/.agents/worktrees` 一个检出目录都没有 → 尚未发生，属潜在风险。

### 3.2 检测三层（全只读）

1. **live**：`sessionProjections.snapshot(session, ['worktree'])`；
2. **冷会话**：`sessionProjectionCache.cachedSnapshot(header, ['worktree'])`；
3. **兜底**：`sessionQuery.readSession(id)` 扫事件，认 `event.ignorable === true && event.type === 'plugin:worktree/created'`；受新配置 `worktreeScanMaxBytes`（默认 8 MB）与 `maxBatch` 约束，超限返回 `unknown: true`。

只统计 `owned: true`（`owned: false` 是 fork 继承引用，不会触发清理）。

### 3.3 路由与交互（已批准的取舍）

| 位置 | 行为 |
|---|---|
| 新路由 `POST /worktrees` | body `{sessionIds}`（≤ maxBatch）→ `{rows, totals}`；宿主未挂工作树服务时 `supported:false`，不报错 |
| 归档前 | **仅命中 ≥1 个工作树时才弹确认框**（否则保持今天的一键归档）：列路径 + 「分支会保留；检出目录与未提交/被忽略的文件会丢失。要保留请在插件页开启『归档时不删除工作树』」 |
| 恢复后 | `POST /unarchive` 响应加 `worktrees`；**toast 文案**提示「曾创建 N 个工作树（分支已保留），需要检出的请用『恢复工作树』」 |
| 详情页 | 已归档且检测到工作树时，操作区**常驻一行提示** |

## 四、兼容、验收与发布

1. wire 只加法：新路由、`preview.skipped`、`unarchive.worktrees`；旧 Client 不受影响。
2. 老宿主：全部 seam 特性检测，缺失时降级为「无工作树信息」，归档不变慢、不失败。
3. 测试：144 → 约 156，全绿为提交前提。
4. 发布（硬规则）：本机构建安装 → **子龙实机验收** → 才打 tag / 发 npm / 同步站点。
5. 文档：本方案、`docs/COMPAT-2026-11-15-dsh-0.2.2-rc.3.md`、`docs/RELEASE-CHECKLIST-0.2.4.md`；兼容矩阵补 `0.2.2-rc.2` / `0.2.2-rc.3`。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 过滤太狠导致某些会话标题没输入 | 标题侧空则退回旧口径；预览侧空态文案说明 |
| 冷会话投影未持久化 `worktree` | 三层兜底；超字节上限诚实报 `unknown`，不假装「没有工作树」 |
| 归档多弹一个框引入摩擦 | 仅命中工作树时才弹 |
| 未来新增 kind | 允许清单 + 兜底 + 一次 `logger.warn` |

## 六、已批准的设计取舍（2026-11-15）

1. 归档弹窗：**仅命中工作树时才弹**（不命中保持一键归档）。
2. 恢复提示：**toast 文案 + 详情页一行提示**。
3. 版本节奏：**0.2.4 一次做完再验收**。

## 七、不做的事

- 不改宿主 `retainOnArchive` 配置本身（只在文案里指路）。
- 不自动调用 `worktree.restore`（恢复检出目录是用户的决定）。
- 不做删除流程的工作树检测（归档时已处理）。
- 不做内容全文搜索、keyset 分页等 ROADMAP 候选（另立版本）。

## 事后补记（实施差异，2026-11-15）

1. **投影读取的真实返回形状是 `{ asOfSeq, values }`，不是裸 key map。** 首版按 `snapshot().worktree` 实现并写了对应 mock，全部测试照样绿；核对 `dsh-session-projection/src/index.ts:514` 与 `dsh-session-projection-cache` 的 `viewRecord()` 后改正为 `snapshot().values.worktree`，并把测试 mock 校正成真实形状，另加一条「投影没有该 key 时落回日志扫描」的用例。**教训：mock 顺着自己的假设写，等于没测。**
2. **日志扫描加了 60 秒进程内缓存**（方案未写）：本机最大 4.1 MB 日志解压约 48 ms，加 JSON 解析约 100–250 ms；缓存避免同一会话重复点击归档时反复扫。创建记录是 append-only，TTL 只为发现 live 会话新建的工作树。
3. `unarchive` 的 `worktrees` 只在 `supported === true` 时附加，且检测异常不影响恢复结果（附加信息是 advisory）。
4. 归档弹窗触发条件按批准口径：`worktrees > 0` **或** `unknown > 0`；两者都没有时保持一键归档。
5. 预览侧不兜底、标题侧兜底，与方案一致；`skipped` 只统计「为填满本次窗口跳过」的条数（不是全会话注入总量）。
6. `unknown` 的三种来源（日志超 `worktreeScanMaxBytes`、fork 继承边界不可知、宿主缺 seam）在 UI 文案里统一写成「未能确认」，不写「没有」。
7. 测试 **164 条**（方案预估 ~156）。
8. 安装方式：`npm pack` 后覆盖 `~/.dsh/profiles/main/node_modules/dsh-session-mng`，旧目录备份在 `/tmp/dsh-session-mng-backup-0.2.3-*`；profile `package.json` 仍写 `0.2.3`（npm 上还没有 0.2.4，避免 `pnpm install` 拉不到），发版后再改。
