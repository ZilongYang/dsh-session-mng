## 结论

**✅ API 零破坏，但有 1 处数据语义变化需要适配（插件 0.2.2 已修）。**

这个插件最深地扎在宿主内部——直接改写 jsonl 首帧、读 `workspaceRegistry` 的私有 Map、按投影缓存拼列表——这些恰恰是最容易在版本升级中被打断的地方。逐项核查后：**存储格式、持久化 API、registry 内部结构、投影读接口、标题服务、会话控制器全部原样保留**。

唯一实质变化是**普通 fork 不再记录来源**（`SessionHeader.parentSession` 不再写入），它不影响任何 API 签名，但会改变插件对「分支会话」的识别与展示——详见 4.3。插件 0.2.2 用 `isSeeded` 兜底识别并区分「来源未记录」，历史 fork 行为不变。

## 四、三个提醒（前两个不需要改代码）

### 4.1 投影注册 API 已异步化

0.2.2 里 `ctx.sessionProjections.register()` 现在返回 `Promise<ProjectionHandle<S>>`（旧同步调用方式保留了运行时兼容，但**新代码必须 await**），同时 `SessionProjectionStateMap` 类型被删除、`ProjectionDefinition` 改为泛型 `ProjectionDefinition<K extends string, S>`。

**对本插件无影响**：只**读**投影、不注册。但若将来要自己注册投影（例如加一个统计投影），必须：

```js
const handle = await ctx.sessionProjections.register({ key, stateVersion, stateSchema, init, apply, wire })
// 并在插件启动阶段持有 handle，用它 stateOf(session) 读
```

### 4.2 `sessionTitle` 服务内部新增 `agents` 依赖

0.2.2 的 `SessionTitleService` 把 `static inject` 从 `['sessions','sessionProjections']` 改为 `['sessions','sessionProjections','agents']`，内部用 `ctx.agents.turnBoundaryOf(session)` 替代 `ctx.sessionProjections.stateOf(session,'turnBoundary')`，并且投影注册搬进了 `Service.init`（异步）。

这是宿主内部重构（含异步 `Service.init` 注册），**本插件不受影响**：`index.js` 声明的 7 个 inject（`webServer` / `sessions` / `sessionQuery` / `sessionPersistence` / `workspaceRegistry` / `sessionTitle` / `llm`）一个都没变，激活不受影响。

`session-title/src/index.ts` 还带一处**行为变化**（不涉及本插件）：自动标题资格从 `parentSession === undefined` 改成 `!isSeeded && origin !== 'subagent'`（即普通 fork 不再触发首次自动标题，仍可按需 `refresh`），条件随 0.2.2 的独立 fork 语义一起调整。

### 4.3 普通 fork 不再记录来源（唯一需要适配的变化）

0.2.2 把这个上游决定真正落地（0.2.1-rc.5 的构建里还没落）：

- `SessionStore.fork()` 删掉了 `parentSession: liveSource.id`（`packages/core/session/src/index.ts`）；
- `sessionController` 的 `fork()` 删掉了 `parentSession: source.header.id`（`packages/api/session-controller/src/commands.ts`）；
- 官方升级指南 `docs/upgrade-guide/v0.2.1-rc.3/independent-session-forks/guide.md`：*"Ordinary forks … omit `SessionHeader.parentSession`; no replacement source field is written"*；
- 宿主自己的 `lineage.ts` 只按 `origin === 'subagent'` 缩进；`SessionHeader.parentSession` 的注释改为「子代理的直接创建者；普通 fork 省略；历史 fork 可能仍带」。

对本插件的影响：分类器此前只按 `parentSession` 判分支，0.2.2 上**新建**的 fork 会被当成根会话（丢徽标 / 缩进 / 父标题 / 搜索命中）。**插件 0.2.2 已适配**：非子代理时把 `isSeeded: true` 也认作普通 fork，区分 `forkLineage: 'recorded' | 'none'`；无来源 fork 显示「分支」+「来源未记录」，不缩进，可单独移动；历史 fork 行为不变。子代理判定不变（`origin: 'subagent'` 优先，委派会话都带该字段）。

## 七、边界说明

- 本文是**源码级契约比对**，不是运行时验证；0.2.2-rc.1 为 RC，正式版可能仍有变化。
- 重点核查了 `packages/session/session-persistence*`、`packages/session/session-projection*`、`packages/session/session-title*`、`packages/session-query/session-query`、`packages/workspace/workspace`、`packages/core/{session,agent}`、`packages/api/{session,workspace}-controller`、`packages/llm/llm`、`packages/host/webserver`。
- 未验证项：`props.close` 的时序、`llm.prepareCall` 备用路径（本插件未用）——两者在插件侧本就无测试覆盖，本次升级也未改动。
- 普通 fork 的来源在新数据中**不可恢复**（官方决定不写替代字段），所以插件对这类分支只能标注「来源未记录」，无法还原父标题。
