# dsh-session-mng 0.2.0 实施计划（Host 侧 overview + 分页 sessions）

> 日期：2026-10-29。状态：**待子龙批准**（批准后本文按原样存档，实施差异另起「事后差异」一节）。
> 目标版本：`0.2.0`。上游依据：`ROADMAP.md` 0.2.0、`docs/HANDOVER-2026-10-27.md` P1。
> 前置：`0.1.4` 已发布；0.1.1 的折叠/分页只在客户端压 DOM，`GET /state` 仍然一次组装全部会话。

## 1. 现状与实测（本机，2026-10-29）

| 指标 | 当前数据 | 推算 10 000 条 |
|---|---|---|
| 会话行 | 107（含子代理 238） | 10 000 |
| `GET /state?subagents=0` | 69.6 KB / 0.30 s | ≈ 6.5 MB / 数十秒 |
| `GET /state?subagents=1` | 160.7 KB / 0.69 s | ≈ 6.7 MB / 数十秒 |
| 宿主全量扫描 | `sessionController.list()` + `sessionPersistence.list()` 各一遍 O(n) | 同上，随会话数线性增长 |

慢在三处：

1. **Host 全量组装**：`lib/state.js` 调 `sessionController.list()`（内部 `sessionQuery.listSessions()` → `sessionPersistence.list()`：readdir + 逐会话读首帧 + stat，并发仅 3）再补一遍 `persistence.list()` 的 size/format，两遍 O(n) 持久化 IO。更慢的是「缺标题」兜底：`readTitleSnapshots(ids)` 对冷会话会**读取整份日志并 replay**，是批量补标题时最贵的一步，新接口必须避免对它做全量调用。
2. **JSON 体积**：每行约 650 B，10 000 行 ≈ 6.5 MB。
3. **Client 单页全量**：`client.js` 拿到全部行后才做 `computeView` 折叠/分页；行多时首屏渲染与搜索都变慢。

结论：只做客户端分页不够，必须把「首屏」变成不含会话行的 overview，把「会话行」变成按工作区分页；且新接口的常规路径不能再批量调用 `readTitleSnapshots` / `sessionController.list`。

## 2. 关键宿主能力（决定实现方式）

已在本机核对 DSH **0.2.1-rc.2**（`~/Library/pnpm/global/.../@deepseek-ai/*` 解包源码）与 **0.2.1-rc.3**（Desktop app.asar 内同一批 per-package 源码），两者一致：

| 能力 | 事实 | 用途 |
|---|---|---|
| `workspaceRegistry.list()` / `entity.sessionIds` | 同步、纯内存，不读持久化；`sessionIds` 顺序=创建时间倒序 + 新会话前插；**含已归档**（归档刻意保留槽位）；entity 无 archived 字段、无每工作区归档列表 | overview 的工作区顺序、会话/归档计数，零会话 IO |
| `workspaceRegistry.archivedSessionIds` / `pinnedSessionIds` | registry 全局**有序数组**（不是 Set），读零 I/O | 归档/置顶状态；每工作区归档数=与 `sessionIds` 求交 |
| `workspaceRegistry.headers` | `Map<id, header>`，启动时由 `sessionPersistence.list()` 一次性建好，**含全部已存储 header**（parentSession/origin/delegationDepth/isSeeded/createdAt/cwd/agentPreset 齐全） | 内存 catalog 的主来源；分类、父子、全局 `forkCount` 都靠它，零额外 IO |
| `sessionProjectionCache.cachedSnapshot(header)` | 零 IO 返回 `title`、`sessionListMetadata{blank,lastPromptAt}`；live 会话用 `sessionProjections.cachedSnapshot(session)`。identity 只有 formatVersion/createdAt/cwd/isSeeded/inheritedEventCount，**没有 origin/parent/字节数** | 标题、更新时间（`max(createdAt,lastPromptAt)`，与宿主列表公式一致）、空会话判定 |
| `sessionPersistence.list()` / `stat(id)` | `list` 是 O(n) 扫盘（3N 次 fs、并发 3）；`stat(id)` 会扫全部项目目录，**不是 O(1)**；`locate(meta)` 按当前格式版本拼文件名，遇到旧代文件会 ENOENT | 只用于「大小统计」与慢路径兜底；页内大小用 `store-jsonl` 的 readdir + 选最高代 |
| `sessionController.list(_request, signal)` | request 被完全忽略：**无 filter/limit/offset/query/sort**；内部 `listSessions()` + 每冷行零 IO 摘要；无分页/增量接口 | 慢路径兜底；新接口常规路径**不得**调用 |
| `sessionQuery.readTitleSnapshots(ids)` | 对冷会话**逐个读取整份日志并 replay**（并发 4） | 现状 `/state` 慢的另一主因；新接口只对**本页缺失标题**做有超时上限的兜底 |
| `sessionQuery.searchSessions` | 只有 SQLite FTS 后端实现；本部署 `dsh-base` 写死 `:memory:` + `openAt:'never'` → 必抛 `SESSION_QUERY_SEARCH_DISABLED`；且 FTS 文本**不含标题** | 0.2.0 **不接**内容搜索；`capabilities.search` 如实上报，标题搜索走内存 catalog |
| `webRuntime` | rc.3 asar 中不存在（0 命中） | fence 恒回退 loopback-only（现状，不影响本计划） |

两个内部 seam 的处理方式与现有 `move` 一致：**特性检测 + 公共 API 慢路径兜底**，缺失时功能降级、不报错、不写坏数据。

- `headers` 是 `Map`（`typeof headers.get === 'function'`、`size` 可读）；
- 投影缓存通过 `ctx.get('sessionProjectionCache')` 取，`cachedSnapshot` 可调用。

已知覆盖缺口（都要在实现里处理）：

- 投影缓存**不保证覆盖**（部署可不挂、刚创建/未到检查点的会话可能没有）：标题按页兜底，`blank` 缺失时按 `false` 处理并标 `unknown`。
- 启动后新建**且未 attach** 的会话可能暂时不在 `sessionIds`：catalog 用 `ctx.sessions.list()` 补齐，按 `cwd` 归组兜底，下一个请求自然收敛。
- `headers` 与磁盘的一致性：本进程删除后需过滤（见 3.5）；外部删除依靠页内 stat 与 `/sizes` 对账收敛。

## 3. Host 设计

### 3.1 内存 catalog（新文件 `lib/catalog.js`）

一次请求内组装，全部来自内存，**零会话日志 IO**：

```
headers(registry) ∪ live(ctx.sessions.list())
  ├─ 标题 / lastPromptAt / blank  ← 投影缓存（live 用 sessionProjections）
  ├─ archived / pinned            ← registry.archivedSessionIds / pinnedSessionIds
  ├─ live / running               ← ctx.sessions.get / ctx.agents.get
  ├─ kind                          ← classifySession（沿用 lib/state.js）
  └─ workspaceId                   ← ledger sessionIds；否则 header.cwd 匹配；否则 ungrouped
再全域计算 parentTitle / parentPresent / forkCount（口径与 0.1.3 完全一致）
```

行字段与 0.1.x `/state` 行保持兼容（`id/title/cwd/workspaceId/archived/pinned/live/running/blank/kind/isFork/isSubagent/parentSessionId/parentTitle/parentPresent/forkCount/agentPreset/createdAt/updatedAt/can`）。`formatStatus` 不常驻 catalog：页内由选中代文件名推断，命中 `/sizes` 缓存时用缓存值，详情由单行 stat 补齐。

`sizeBytes` 不在内存 catalog 里：只在「返回页」和「/session 详情」时按 id 读取当前日志文件大小（≤50 个文件 stat）。

### 3.2 新接口（全部 GET，与既有前缀同一 fence/错误信封）

| 路由 | 说明 |
|---|---|
| `GET /overview?subagents=0\|1` | 不含任何会话行 |
| `GET /sessions?workspaceId=<id>\|ungrouped&tab=all\|active\|archived&query=&sort=updated\|created\|title\|size&offset=0&limit=50&subagents=0\|1&blank=0\|1&sizes=0\|1` | 单工作区一页；`limit` 上限 50 |
| `GET /search?query=&tab=&sort=&subagents=&blank=&limitPerGroup=50` | 跨工作区搜索：返回每个命中工作区的 `{total, rows[≤50]}`，供客户端自动展开 |
| `GET /session?id=` | 详情单行（含 size/formatStatus/can/parent/forkCount） |
| `GET /blanks?subagents=0\|1` | 空会话 id 列表：`{unarchivedIds, archivedIds, deletableIds}` |
| `GET /sizes?workspaceId=<id>\|all` | 大小统计（缓存；见 3.4） |

**`/overview` 返回**：

```json
{
  "generatedAt": 0,
  "source": "catalog" ,
  "workspaces": [{ "id": "", "title": "", "path": "", "status": "ok",
                   "count": 0, "activeCount": 0, "archivedCount": 0,
                   "blankCount": 0, "totalBytes": null }],
  "ungrouped": { "count": 0, "activeCount": 0, "archivedCount": 0, "blankCount": 0 },
  "totals": { "all": 0, "active": 0, "archived": 0, "subagents": 0,
              "hiddenSubagents": 0, "forks": 0, "blank": 0, "bytes": null },
  "orphans": [],
  "capabilities": { "title": true, "move": true, "delete": true, "search": false, "backend": "jsonl" },
  "limits": {}, "backend": "jsonl"
}
```

计数口径与 `lib/state.js` 完全一致（`totals.all` 为可见行数；隐藏子代理计入 `hiddenSubagents`；`blank` 是隐藏空会话的计数），实现时用同一份 fake ctx 断言 `overview` 与 `buildState` 相等。`capabilities.search` 表示宿主内容搜索是否可用（本部署为 `false`，UI 只做标题搜索，不假装有全文搜索）。

**`/sessions` 返回**：

```json
{ "generatedAt": 0, "workspaceId": "", "total": 0, "offset": 0, "limit": 50,
  "hasMore": false, "titlesPending": 0,
  "rows": [ { "...": "同 /state 行", "sizeBytes": 0,
    "parentStub": { "id": "", "title": "", "present": true } } ] }
```

- Host 先在**整个过滤集**上做 branch-aware 排序（父行的排序键优先、同父内按 `sort`、最后 `id` tie-break），再 `slice(offset, offset+limit)`；`total` 是过滤后的总数，`hasMore` 直接由此得出。
- fork 行的 `parentTitle`/`parentPresent` 一律按**全域**计算；父不在本页时附 `parentStub`，客户端据此显示「↳ 来自：X」而不是「来源父会话已不存在」。
- `forkCount` 一律全域计数（不随搜索/分页变化），保持 0.1.3 的「N 分支」与详情移动提示。
- `showBlank` 关闭时在**分页前**剔除 blank 行，`total/hasMore` 同步是剔除后的数。
- 标题常规路径只用投影缓存；缓存缺失的本页行才做 `readTitleSnapshots` 兜底（单个请求总预算 2 s、只对本页 ≤50 条），仍无结果则标题为空并计入 `titlesPending`（客户端显示占位，不阻塞）。

**`/session` 返回**：`{ "row": {}, "capabilities": {}, "limits": {} }`。

### 3.3 排序与分页稳定性

- 排序键：`updated` = `max(header.createdAt, sessionListMetadata.lastPromptAt)`（与宿主 `sessionController.list` 的公式一致）；`created`；`title`；`size`（见 3.4）。
- 所有排序都追加 **`id` 升序 tie-break**，避免同值行在页间重复/漏行。
- 0.2.0 先用 **offset 分页**（实现简单、支持「回到第 N 页」与整组刷新）；响应带 `generatedAt`，写操作后客户端丢弃旧页并重取当前展开组，不做客户端算术调和。`(sortValue,id)` keyset 游标列为后续优化（宿主已给稳定 tie-break，切换成本低）。
- `sort=size` 依赖全量大小：若大小缓存未就绪，先做一次该 scope 的扫描（上限 `sizeScanMax`，默认 20 000 会话 / 20 s 超时），失败返回 `sizes-pending` 让客户端降级提示，**不**静默按 0 排序。

### 3.4 大小统计（唯一的 O(n) IO，且不在关键路径）

- 页内行：`store-jsonl` 的 `findSessionDirs` + `currentLogFile`（readdir 后选**最高代**文件，避免 `locate` 按当前格式拼名遇到的旧代 ENOENT）+ `stat`，只读本页 ≤50 个文件；`formatStatus` 由选中的代文件名推断（最高代即 `current`）。
- 工作区/全局总量：`GET /sizes` 调一次 `sessionPersistence.list()`（同时可对齐幽灵行、拿准确的 `formatStatus` 与 `sizeBytes`），按工作区聚合，进程内缓存 `sizesTtlMs`（默认 60 s）；归档/恢复/移动/删除/标题写入后失效。该结果同时作为页内 size 的优先来源，命中缓存时页请求无需再 stat。
- 客户端首屏不等待大小：先用 overview 渲染计数，`/sizes` 在后台请求，回来后补「总大小 / 组大小」；失败或超时显示「—」。

### 3.5 一致性处理

- **删除后的幽灵行**：`remove()` 成功后进程内记 `deletedIds` 并从 `catalog` 过滤；尽力 `registry.headers.delete(id)`（已有 headers seam 先例，失败不影响结果）；`/sizes` 的 `persistence.list()` 结果用作对账，把已不存在的 id 从 catalog 候选集剔除。
- **冷会话标题刚写入**：`title/apply` 对 cold 会话不经过宿主投影缓存，可能在下次 fold 前显示旧标题；写入成功后记进程内 `titleOverrides: Map<id, {title, at}>`，catalog 优先使用，`/sizes` 对账或进程重启后自然消除。
- **外部变更 / 新会话**：catalog 每次请求都合并 `ctx.sessions.list()`；未 attach 的新会话按 `cwd` 归组，下一个请求收敛。外部进程的删除/改名由页内 stat 与 `/sizes` 对账收敛，不追求跨进程实时一致（与 0.1.x 的「刷新即准」一致）。
- **慢路径**：`headers` 或投影缓存缺失时，`catalog` 回退为「`buildState()` 组装 + 30 s TTL 缓存」，接口形状不变（`source: "legacy"`），客户端无感。这条兜底保证插件在未知宿主版本上仍然可用，只是回到 0.1.x 的性能。

### 3.6 兼容

- `GET /state` **原样保留**给 0.1.x 客户端；Host 同时提供新旧接口。
- 新路由参数/边界校验失败返回既有错误信封（`bad-request` 等），未知路由 404。
- 版本升到 `0.2.0`；`dsh.compatibility` 维持 `>=0.2.0-rc.1 <0.3.0-0`。

## 4. Client 改造（`client.js`）

1. **数据层**：`overview` 首屏 + 每工作区 `pages` 缓存（`{rows,total,offset,hasMore,phase}`）+ `rowCache`；`scopeKey = tab|workspaceFilter|query|sort|includeSubagents|showBlank` 变化时清 `pages`/选择，`overview` 单独按 `generation` 失效；每组一个 `AbortController` + 请求代次，过期响应丢弃；展开/`expandAll` 并发上限 3。
2. **首屏换源**：tabs 计数、`totalLine`、`hiddenSubagents`/空会话计数、orphan 横幅改用 `overview`；空会话两个按钮改用 `/blanks` 的 id 列表；`state.limits`/`state.workspaces` 改 `overview.limits`/`overview.workspaces`；`defaultExpanded` 仍用 `totals.all <= 100`。
3. **展开 / 加载更多**：展开时取 `offset=0&limit=50`；`loadMore` 取下一页并 append（按 id 去重）；`Group` 用 `total - rows.length` 显示剩余、组头大小用 `/sizes`，不再用已加载行 Σ。
4. **搜索**：`queryInput` 与 `query` 分离（防抖 250–300 ms）；`query` 走 `/search`，命中组自动展开（保持 `locked`）；`haystack` 对齐 0.1.3（title + cwd + id + parentTitle）。
5. **选择**：只允许选**已加载且已展开**的行；`scopeKey` 变化清空选择；`全选` 只作用于已加载可见集并提示「另有 N 条未加载」；批量提交前过滤掉不在 `rowCache` 的 id（数据安全）。
6. **分支跨页**：父在已加载行内 → 缩进挂父；父存在但未加载（`parentStub.present`）→ 顶层 + `↳` + 「来自：父标题」；`parentPresent === false` 才显示「来源父会话已不存在」；新增中性兜底文案「来源父会话未加载」。
7. **详情**：`openDetail(id)` 先查 `rowCache` 立即渲染，同时 `GET /session` 补齐/刷新；**删除** `client.js:1492-1495` 的「不在 `state.sessions` 就关闭详情」；`DetailView` 入参改 `{overview, limits, row}`；返回列表时保留页缓存与滚动位置。
8. **刷新**：新增 `refresh()`：重取 overview + 对当前展开组按「已加载条数」重取 offset=0 页，保留选择与滚动；写操作后按影响范围失效（归档/恢复/移动失效相关组，删除额外清 `rowCache`）；`window.focus` 只静默刷 overview 并标记页面 `stale`，不再全量重取。
9. **i18n**：中英各补 `groupLoading`、`groupLoadFailed`、`groupRetry`、`loadedOf`、`partialSelection`、`parentNotLoaded`、`overviewLoadFailed`、`sizesPending`。
10. **回退开关**：`GET /overview` 404 → 一次性探测失败，回退 `GET /state` 并沿用 0.1.4 的旧逻辑（保证老 Host + 新 Client 的组合可用）。

- 现有 29 个测试全绿；`node --check`；`npm pack --dry-run`。

**实机验收（只读为主，写操作只用一次性测试会话）**

- `/overview` 不含会话行；展开工作区只发一页请求；不出现全量 `/state`。
- 分支跨页文案正确（父未加载 ≠ 父已删除）；搜索父标题仍命中分支。
- 空会话「归档空会话/清理空会话」按钮仍在且可用；orphan 清理可用。
- 详情进入/刷新/返回列表不闪退；归档/恢复/移动/删除后列表与计数一致。
- 1000 / 10 000 条合成数据用 `/tmp` 假数据目录验证；不提交真实标题/路径。

## 7. 不做（留给后续）

- 全文内容搜索（宿主 FTS 依赖 + 需要可与标题搜索合并的结果模型）。
- 虚拟滚动（分页后不再是瓶颈）。
- 整枝移动、导出、置顶、回收站、非 JSONL 后端、跨主机迁移。
- 自动标题 provider / 自动归档规则。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 内部 seam（`registry.headers`、`sessionProjectionCache`）在宿主升级后变形 | 每次访问都特性检测；缺失走 `buildState` 慢路径；版本敏感点写进 README |
| 投影缓存覆盖不足（未挂载 / 新会话未落检查点） | 标题只对本页缺失行做 2 s 预算的 `readTitleSnapshots` 兜底；`blank` 缺失按未知处理；overview 计数允许「短时偏低」并在刷新后收敛 |
| 幽灵行（外部删除 / 本进程删除后 header 缓存未清） | 进程内 `deletedIds` + 尽力 `headers.delete`；`/sizes` 对账；页内 stat 失败即剔除 |
| 冷会话标题写入后缓存滞后 | 进程内 `titleOverrides` 优先；重启/对账后自然消除 |
| 分支跨页把「未加载」谎报成「已删除」 | `parentPresent` 全域口径 + `parentStub` + 中性文案兜底 |
| 选择集误伤未加载行（数据安全） | loaded 语义 + `scopeKey` 清空 + 提交前过滤 |
| `focus`/`expandAll` 请求风暴 | overview 单独刷新 + 页面 staleness + 并发上限 3 |
| `sort=size` 触发 O(n) 扫描 | 只按需、带上限与超时，失败明确提示，不静默错排 |
| offset 分页在数据变化后漂移 | `id` tie-break + `generatedAt` 失效 + 刷新当前展开组；后续可切 keyset |
| 计数口径漂移（tab/blank/subagent） | overview 与 buildState 同 fake ctx 断言；分页前过滤 |
| 宿主无字节索引，`/sizes` 在 10k 时可能 5–20 s | 异步、可取消、TTL 缓存；首屏与分页完全不依赖它 |

## 9. 待子龙确认（推荐项已标注）

1. **范围**：0.2.0 一次做完 Host + Client（推荐）；或先发 Host-only 0.2.0、客户端 0.2.0 之后再发 0.2.1。
2. **零 IO catalog**：接受把 `workspaceRegistry.headers` 与 `sessionProjectionCache` 作为特性检测的快速路径（推荐，已有 move seam 先例；否则只能维持 O(n) 全量扫描，达不到首屏目标）。
3. **大小策略**：页内行按需 stat、总量异步 `/sizes`（推荐）；或 0.2.0 暂时去掉大小显示。
4. **搜索范围**：0.2.0 用内存 catalog 做标题/路径/id 搜索（推荐），全文内容搜索留后续；或 0.2.0 就接入宿主 FTS（依赖 sqlite 后端，结果模型不同）。
5. **客户端测试**：接受 B0 的 `node:vm` 纯函数测试（推荐，零构建依赖）。
