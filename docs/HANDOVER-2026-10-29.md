## 2. 0.2.0 做了什么

目标：真正支撑 1000–10000 条会话，首屏不再拉全量 `state`。

- **Host catalog（`lib/catalog.js`）**：只用宿主已有的两块内存数据组装会话行——`workspaceRegistry.headers`（启动时由 `sessionPersistence.list()` 建好的全量 header Map）与 `sessionProjectionCache`（title / `sessionListMetadata{blank,lastPromptAt}`；live 会话用 `sessionProjections.cachedSnapshot`）。常规路径**不调用** `sessionController.list()` / `sessionPersistence.list()` / 批量 `readTitleSnapshots()`。两个 seam 全部特性检测，缺失时回退 0.1.x 的 `buildState` + 30 s TTL，接口形状不变。
- **7 条只读路由**（`lib/api.js`）：`/overview`、`/sessions`、`/search`、`/session`、`/blanks`、`/sizes`，以及保留的 `/state`。契约见 `PLAN-2026-10-29.md` 3.2 与 `RELEASE-CHECKLIST-0.2.0.md`。
- **Client 两段式**：首屏 overview → 展开取一页（≤50）→ 加载更多 offset 追加；搜索走宿主；选择只作用于已加载行；详情走 `/session`；老 Host 404 回退 `/state` 并保留每组 50 条本地分页。
- **性能基准（10k 合成）**：overview 9.5 ms / 1338 B；单页 8.8 ms / 50 行 / 25.3 KB；全量扫描调用 0 次。

### 不要改坏的行为

- `/state` 必须继续可用（0.1.x 客户端与老 Host 回退都依赖它）。
- 计数口径：`overview.totals.all` 是 subagents 过滤后的可见行数；`blank` 仍计入行、只是客户端隐藏；`/sizes` 与 `overview` 同口径。
- 分页稳定：所有排序必须有 `id` tie-break；`generatedAt` 变化后客户端重取当前展开组。
- 选择安全：scope 变化清空选择；批量提交前过滤不在 `rowCache` 的 id。
- 分支跨页：`parentPresent` 是**全域**是否存在；父未加载≠父已删除，用 `parentStub`/`parentNotLoaded` 区分。

## 6. 环境与坑

- DSH `0.2.1-rc.3`；Desktop `desktop` profile **由应用独占**，不要用 `dsh plugin --profile desktop …` 管理；用应用内插件管理器或 `plugin_manager`。
- **两个内部 seam**：`workspaceRegistry.headers`（`Map<id, header>`，启动后新建且未 attach 的会话可能暂缺，靠 live 合并）与 `sessionProjectionCache.cachedSnapshot(header)`（identity 无 origin/parent/字节数）。升级 DSH 先跑测试 + 实机；seam 变形时自动走慢路径，不会失败。
- `sessionPersistence.stat(id)` 会扫全部项目目录，**不是** O(1)；页内大小用 `readLogFacts`（readdir+stat）。
- 本部署 `sessionQuery.searchSessions` 不可用（dsh-base 写死 `:memory:` + `openAt:'never'`，抛 `SESSION_QUERY_SEARCH_DISABLED`），且 FTS 文本不含标题；所以 0.2.0 的搜索是内存 catalog 的标题/路径/id 搜索。
- `webRuntime` 在 rc.3 中不存在 → fence 恒回退 loopback-only（现状，不影响）。
- 测试/截图只用一次性测试会话或 `/tmp` 假数据；不要提交真实标题/路径/会话 id。
- 不要为了验收起第二个 DSH 实例指向同一个 `~/.dsh`（storage domain / 投影缓存是单进程所有者）；需要隔离时用独立 `DSH_HOME`，但那样没有真实投影缓存，只能验证慢路径。
