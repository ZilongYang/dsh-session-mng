# dsh-session-mng 0.1.1 实施计划（会话列表可用性修复）

> 日期：2026-10-27。来源：子龙在 0.1.0 交付后提出的三个问题。已确认的选择：
> 1. 大列表：**0.1.1 快修 + 0.2.0 分页**；
> 2. 选择联动：**裁剪到可见集**；
> 3. 吸附：**过滤区 + 批量区一体吸附**。

## 1. 问题

1. 默认平铺全部会话；202 条时 state 约 103 KB，10000 条会到 MB 级、DOM 一万行，首屏和滚动都不可接受。
2. 只有批量条 sticky，过滤区滚走后看不到当前 tab/工作区/搜索条件。
3. 已选集合独立于过滤条件；切换筛选后批量操作仍可能作用于不可见会话。

## 2. 0.1.1 范围（客户端改动，Host API 不变）

### 2.1 工作区优先 + 客户端分页

- `总会话数 > 100` 时默认全部工作区折叠；`<= 100` 保持展开。
- 点击工作区标题展开/收起；提供「展开全部 / 收起全部」。
- 每个工作区默认渲染 50 条，`加载更多（剩余 N）` 每次 +50。
- 搜索/筛选命中时自动展开命中的工作区；搜索期间禁用折叠并提示“搜索时自动展开命中工作区”。
- 分组头显示会话数、总大小；折叠时只渲染头部，不渲染行。

### 2.2 吸附

- 过滤工具栏 + 批量条合并为一个 `.dsm-sticky`：`position: sticky; top: 0`，背景 `--dsw-alias-bg-base`，底部分隔线；批量条不再是独立 sticky。
- 列表操作条（展开全部/收起全部、选择范围提示）放在 sticky 块下方，随内容滚动。

### 2.3 选择裁剪到可见集

- 可见集 = 当前 tab/工作区/搜索过滤后的行 ∩ 已展开的工作区（搜索时自动展开）。
- 过滤、折叠、搜索、刷新、切换“显示子会话”后，`selected = selected ∩ 可见集`；为空自动清空。
- 批量操作只使用可见的已选行；`全选当前列表` 只选当前可见集。
- 批量条加提示：“选择仅作用于当前筛选与展开结果。”

## 3. 非目标（留给 0.2.0）

- 不做 Host 侧 overview/paged sessions 接口；首屏仍然拉全量 state（0.1.1 只压 DOM，不压 payload）。
- 不做未分组懒加载、全局内容搜索、虚拟滚动。
- 10000 条量级的真正分页、计数和全局搜索在 0.2.0 做。

## 4. 验收

- 202 条真实数据默认折叠；展开单个工作区只渲染 50 行；加载更多正常。
- 搜索命中时自动展开；折叠在搜索期间禁用。
- 过滤/折叠/搜索/刷新后已选集合被裁剪；批量操作不触碰隐藏行。
- 滚动时过滤区 + 批量条一起吸顶；详情打开/返回滚动位置正常。
- `node --test` 全绿；`npm pack` 正常；实机 UI 截图更新。
- 0.1.1 发布后验证版本端点；市场条目无需改 YAML（npm 版本自动更新）。

## 5. 发布清单

- 更新 `package.json` 0.1.1、`CHANGELOG.md`、`ROADMAP.md`、README。
- 新增 `docs/RELEASE-CHECKLIST-0.1.1.md`。

## 事后差异（补记，2026-10-27）

1. **默认折叠阈值定为 100**：计划只写“>100 默认折叠”，实现按 `totals.all <= 100` 展开、`>100` 折叠；当前 202 条会默认折叠。
2. **自动展开只对搜索生效**，不是对所有 tab/工作区筛选生效。计划原文写“搜索/筛选命中”，实现选择“搜索命中自动展开；tab/工作区筛选保留折叠状态，由用户点击”。这样避免切 tab 时整页突然铺开；如需“工作区筛选自动展开”可在 0.2.0 数据流重构时一起做。
3. **可见集 = 过滤结果 ∩ 已展开工作区**；分页只影响渲染，不影响可见集。因此「全选当前列表」会选中已展开工作区中所有过滤行（包括尚未点“加载更多”的行），批量条显示真实数量。这样做是为了避免“分页把已选行变成隐藏行”的歧义。
4. **批量移动提示拆分**：选中 live 会话时显示原来的“已打开不能移动/删除”；其他不可移动原因（跨工作区、有子会话、状态未就绪）显示新的通用提示。
5. **新增第 4 张截图** `screenshot-4-expanded.png`，展示工作区展开、选择 2 条活跃会话、sticky 过滤 + 批量条；市场可展示 4 张。
6. **实现中修了一个行选择事件绑定 bug**：Group 的行 checkbox 最初误调用工作区折叠函数（`toggleGroup`），已拆成 `onSelect` / `onToggle` 两个 prop；该 bug 只存在于工作区，未进入 0.1.0 发布。
7. **0.1.1 仍是客户端快修**：首屏继续拉全量 state（202 条约 103 KB；10000 条约 5 MB），真正按工作区懒加载/分页在 0.2.0 做。这一点在验收时明确，不把 0.1.1 当成 10000 条的解决方案。

8. **发布结果（2026-10-27）**：0.1.1 已发布；npm `latest` = 0.1.1（31 文件，560.7 kB），GitHub main / tag `v0.1.1` / Release 已更新；marketplace 条目不变，版本随 npm 自动更新。
