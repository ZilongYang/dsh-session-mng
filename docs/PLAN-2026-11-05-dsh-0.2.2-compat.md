# dsh-session-mng 0.2.2 实施计划：DSH 0.2.2-rc.1 兼容适配（独立 fork）

> 批准时间：2026-11-05。本文按批准内容原样存档，实施后与计划的差异另起一节补记。
> 依据：`docs/COMPAT-2026-11-05-dsh-0.2.2-rc.1.md`（源码级契约比对，须一并修正）与两个 release tag 的复核。
> 目标版本：插件 `0.2.2`。

## 背景

桌面 App 实际已运行 **DSH 0.2.2-rc.1**（`Info.plist` = 0.2.2-rc.1，2026-11-04 安装；全局 `dsh` CLI 仍是 0.2.1-rc.5，之前文档把两者混了）。0.2.2 把「普通 fork 是独立会话」真正落地：

- `SessionStore.fork()` 与 `sessionController.fork()` 都删除了 `parentSession: source.id`，官方升级指南写明「no replacement source field is written」；
- 宿主自己的侧栏 `flattenLineage` 只按 `origin === 'subagent'` 缩进；
- 历史 fork（旧日志）仍保留 `parentSession`，含义不变。

本插件三态模型（根 / 分支 / 子代理）只按 `parentSession` 判分支，因此 **0.2.2 上新建的 fork 会被当成根会话**：没有「分支」徽标、不缩进、没有来源提示。历史 fork 不受影响。

另：0.2.2 给 `ctx.sessionProjections.cachedSnapshot()` 标了 `@deprecated`（"never use it to decide behavior"），插件的 live 快路径仍依赖它，计划顺手迁移到受支持的 `snapshot()`。

## 批准结论（子龙 2026-11-05）

1. 采用 **方案 A**：0.2.2 起新建的 fork 仍显示为「分支」，标注「来源未记录」，不缩进，允许单独移动；历史 fork 行为不变。
2. `cachedSnapshot → snapshot()` 迁移一并做。
3. 宿主已是 0.2.2-rc.1，验收直接在本机 App 里做，不另装临时实例。

## 需求与验收口径

| # | 场景 | 期望 |
|---|---|---|
| 1 | 0.2.2 新建的普通 fork（`isSeeded:true`、无 `parentSession`、非子代理） | 列表有「分支」徽标；来源行显示「来源未记录」（不是「来源父会话已不存在」）；不缩进；详情可移动；`totals.forks` 计入 |
| 2 | 历史 fork（有 `parentSession`，父还在） | 与 0.2.1 完全一致：缩进、父标题、`N 分支`、不可单独移动 |
| 3 | 历史 fork（有 `parentSession`，父已删除） | 与 0.2.1 一致：「来源父会话已不存在」 |
| 4 | 子代理（`origin:'subagent'` 或 `delegationDepth>=1`） | 仍判定为子代理：默认隐藏、整枝移动、级联删除 |
| 5 | 普通会话 | 行为不变（根会话、可移动） |
| 6 | live 投影读取 | 走 `sessionProjections.snapshot()`，`cachedSnapshot` 仅作旧宿主兜底 |
| 7 | 回归 | 列表/分页/搜索/标题/归档/恢复/移动/删除全部不受影响 |

## 实施内容

### P1 Host（`lib/state.js`）

- `classifySession(fields)`：非子代理分支判据改为
  1. 有 `parentSession`/`parentSessionId` → `fork`（历史 fork，语义不变）；
  2. 否则 `isSeeded === true` → `fork`（0.2.2 的无来源普通 fork）；
  3. 否则 → `root`。
- `classifyKind(header, summary)` 把 `header.isSeeded` 传下去（`SessionSummary` 没有该字段，只能取 header）。
- 行新增 wire 字段 `forkLineage: 'recorded' | 'none'`（仅 `kind==='fork'`），供 Client 区分「有父但父没了」与「本来就没记录来源」。
- `canOf(row, capabilities)` 的移动条件：`root`，或 `fork && forkLineage==='none'`（0.2.2 里这种 fork 是独立会话，`moveOne` 本来也放行；否则会出现界面不给按钮、API 能移动的口径不一致）。
- 子代理判定、`partitionDescendants`、整枝移动、级联删除、`forkCount` 统计逻辑不动。

### P1 Host（`lib/catalog.js`）

- `rowFromHeader`：`forkLineage` 同上；分类继续用 header（含 `isSeeded`）。
- `attachRelations` / `orderBranchRows`：无来源 fork 作为顶层行，不参与缩进与 `forkCount`。
- `publicRow`：输出 `forkLineage`（无该字段时 `null`，保持 wire 形状稳定）。
- `liveBlock`：优先 `registry.snapshot(session, ['title','sessionListMetadata'])`；旧宿主无 `snapshot` 时回退 `cachedSnapshot`。
- `projectionRegistry` 的存在性判断从「有 `cachedSnapshot`」放宽为「有 `snapshot` 或 `cachedSnapshot`」。

### P1 Client（`client.js`）

- i18n 新增 zh/en：`branchSourceUnknown`（来源未记录 / Source not recorded）、`branchSourceUnknownHint`（说明 0.2.2 起普通 fork 不再记录来源会话）。
- `annotateBranchRows`：`kind==='fork' && parentSessionId===null` 的行标 `branchSourceUnknown`，不再落入「父已不存在」分支。
- 列表行副行、详情「父会话」行、徽标 title 分别按 有父 / 父缺失 / 无来源记录 三种情况渲染。
- 无来源 fork 的移动按钮由 `row.can.move` 决定（Host 已放开）。

## 风险与回退

- `isSeeded` 兜底误判风险：子代理均带 `origin:'subagent'`（`packages/subagent/subagent/src/child-agent.ts`），会先被排除；将来若出现新的「seeded 但非 fork」会话类型，按 `origin`/`delegationDepth` 扩展判据即可，改动点集中在 `classifySession`。
- `snapshot()` 是同步内存折叠，仅对 live 会话调用（数量少）；若某个宿主版本行为异常，`liveBlock` 的 try/catch 与 `readPageTitles` 兜底仍在，最坏退化为标题晚到。
- 回退方式：`git revert` 本版本提交即可；新增 wire 字段是纯加法，旧 Client 忽略之。
