## 四、顺带查出并修掉的真问题：系统注入被当成用户消息

实测 `POST /session-mng/api/preview`（会话 `b5946f88…`）返回 5 条「用户消息」，**全部是系统注入**：`<system-reminder>`、技能目录、时间上下文、MNEMON 记忆快照。

120 个会话日志的 `user/message` 事件分布：

| `source.kind` | 条数 | 性质 |
|---|---|---|
| `user` | 315 | 真人输入 |
| `time-context` | 304 | 每轮注入快照 |
| `runtime-context` | 151 | 运行时提醒快照 |
| `dsh-mnemon` | 148 | 记忆 instructions / snapshot / recall |
| `skill-catalog` | 45 | 技能目录 |
| `user-approval` / `tool-jobs` / `subagent-settled` | 12 / 12 / 9 | 通知 |
| `agent-message`（relay） | 9 | 其他 agent 发的真实内容 |

合计 1005 条，真实对话仅 324 条（**32%**）。0.2.4 起按 `source.kind` 白名单过滤（`user` / `agent-message` / 无 `source`），标题侧空则回退旧口径，预览侧不兜底。

## 五、归档 × 工作树（rc.2 起的行为变化）

- 工作树服务把创建的检出目录记成 `plugin:worktree/created` 记录（`ignorable: true`）；
- 归档时若该记录 `owned: true`、无未归档会话引用、策略非只读、Git 检查干净 → `git worktree remove`（分支保留，未提交/被忽略文件丢失）；
- `retainOnArchive` 默认关闭；
- 本部署此前没有任何 `.agents/worktrees` 检出目录，因此该变化**尚未实际发生**，属潜在风险。

0.2.4 的处理：`lib/worktrees.js` 三层只读检测 + `POST /worktrees` 预览；归档前仅命中时确认；恢复 toast 与已归档详情页提示；不改 `retainOnArchive`、不自动 `worktree.restore`。
